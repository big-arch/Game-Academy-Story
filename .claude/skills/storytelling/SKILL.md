# Сторителлинг «Мастерской историй»

Игра — уютный ремонт старой техники. Каждая вещь несёт чью-то историю; игрок раскрывает её руками: осматривает, разбирает, находит, чинит. Источники: `docs/SCENARIO.md` (сюжет сезона), `docs/GAME-RESEARCH.md` (механики).

## Где что лежит

- `stories.js` — клиенты: `id, name, title, intro, questions[2], ending, marks[], find?`.
- `memories.js` — экран устройства после ремонта (сообщение, запись, фото) и продолжение.
- `devices.js` — поломка устройства (`outside`, `inside`, `causes`, `fixes`); история клиента должна объяснять поломку («пролил чай» → липкие контакты).

## Формула заказа

1. **Крючок (intro)** — 1–2 предложения, прямая речь в «ёлочках». Отвечает: что сломалось + почему это важно *сейчас* (срок, событие, человек).
2. **Два вопроса** — первый про вещь/прошлое, второй про человека/будущее. Ответ ≤ 2 предложений, с одной конкретной деталью (имя пса, год, место).
3. **След снаружи (marks)** — 0 или 1, редко 2. Только если след рассказывает новое: кто, когда, почему. Виды: `sticker-star`, `sticker-heart`, `sticker-smile`, `scratch`, `bite`, `tape`.
4. **Находка внутри (find)** — 0 или 1: `note`, `photo`, `ticket`. Это «тайна», о которой клиент не знал или забыл. Самый сильный момент заказа — не трать на мелочи.
5. **Экран после ремонта** — то, ради чего несли вещь. Конкретный текст, а не «там фото».
6. **Финал (ending)** — короткая сцена после возврата, с улыбкой или комком в горле. Без морали, без «спасибо, что починили» в лоб.

## Правила тона

- Русский язык, живая речь, бытовые детали 80–90-х и сегодняшнего дня.
- Юмор мягкий: коты, пироги, ворчливые деды, «это кринж» от подростков.
- Грусть допустима (ушедшие родные), но финал всегда тёплый.
- Никаких торговых марок и реальных брендов, реальных песен и фильмов по названию (пиши «новогодняя комедия», «песня про кузнечика»).
- Не повторять крючки: проверь, что событие (свадьба, юбилей, финал) не встречается у другого клиента того же устройства.
- Причина поломки в истории = правильная причина в `devices.js`.

## Связь со сценарием

- Каждый 4–5-й клиент — из сквозных персонажей (`docs/SCENARIO.md`) или упоминает Лёву-мастера.
- Предметы с полки «НЕ ГОТОВО» имеют бирку и связаны с «Н.».
- Возвращающийся клиент ссылается на прошлый заказ одной фразой.

## Проверка перед сохранением

- [ ] intro ≤ 220 символов, ответы ≤ 180, ending ≤ 200.
- [ ] Есть конкретная деталь в каждом ответе.
- [ ] Следов ≤ 2, находок ≤ 1; координаты лежат на корпусе (закрытый вид) / внутри (открытый).
- [ ] Поломка из истории совпадает с `correct`-причиной устройства.
- [ ] `npm test` проходит (проверка контента клиентов).
- [ ] Прогнать заказ в браузере: диалог → ремонт → экран → финал.

## Пример

```js
{
  id: 'sveta', name: 'Светлана', title: 'Последнее сообщение',
  intro: '«Это пейджер мужа. Он служил на севере и присылал мне сообщения. Пейджер давно молчит, а там последнее, которое я так и не дочитала.»',
  questions: [
    { q: 'Почему не дочитали?', a: '«Батарейка села прямо на середине. Я подумала — приедет и расскажет. Тридцать лет прошло.»' },
    { q: 'Он вернулся?', a: '«Вернулся. Только про сообщение говорит: «Не помню». Хитрит, по глазам вижу.»' },
  ],
  ending: '«Там написано: «Вернусь к весне. Люблю. 143»… Вот хитрец.»',
  marks: [{ id: 'heart', kind: 'sticker-heart', x: 82, y: 22, size: 9, text: 'Сердечко Светлана наклеила перед проводами на вокзале.' }],
  find: { id: 'find', kind: 'note', x: 70, y: 30, text: 'Под платой — записка мужа: «Если сядет батарейка — значит, я уже еду».' },
}
```
